# @podosoft/podokit-auth

PodoKit's DB-backed auth **configuration pipeline** — the layer that sits on top
of [better-auth](https://better-auth.com) so OAuth providers, SMTP, and
server-enforced policies, including automatic logout, can be managed at runtime (from an admin Settings page)
instead of being frozen in environment variables at boot.

It is deliberately free of better-auth and web-framework/ORM imports (only
`node:crypto` and a `pg` peer), so it can be loaded outside dependency injection
and by the `@better-auth/cli` during migrations.

## What's inside

- **Envelope-encrypted secrets** — `encryptSecret` / `decryptSecret` store OAuth
  client secrets and the SMTP password with AES-256-GCM. The key is derived from
  `BETTER_AUTH_SECRET` via HKDF-SHA256 and never lives in the database it
  protects, so a DB leak alone can't decrypt them.
- **The `AuthConfig` model** — the shape of the runtime config (social providers,
  SMTP, and server policies including provider-independent sign-up approval and
  a validated session idle timeout), plus
  `envAuthConfig()` (the env-only fallback),
  the supported-provider allowlist, and `socialKey` helpers.
- **A config store** — `createConfigStore(pool)` loads the current config from
  the `auth_config` table (with per-field env fallback) and decrypts secrets in
  memory. It serves one snapshot for a short TTL (3 seconds by default). After
  the TTL it runs one cheap version probe (`count(*)` and `max("updatedAt")`)
  and reads a table again only when the probe changes, so a deleted row is
  detected too. Values derived from a snapshot (the decrypted config, the
  capabilities snapshot, the SMTP config) are computed once per change.

## Install

```sh
npm install @podosoft/podokit-auth
```

`pg` is a peer dependency (your app already provides it).

## Usage

```ts
import { createConfigStore, envAuthConfig } from "@podosoft/podokit-auth";

const store = createConfigStore(pool);      // reads auth_config, env fallback
const config = await store.load();          // AuthConfig (secrets decrypted)
const smtp = await store.smtpConfig();      // resolved SMTP transport config, or null
store.invalidate();                         // after a local write: reload on next read
```

A repository can also share the snapshot with a key/value settings table and
supply its own probe, for example to cover both tables in one statement:

```ts
const store = createConfigStore({
  list: readAuthConfigRows,                 // auth_config rows
  listSettings: readAppSettingRows,         // { key, value } rows
  versions: readVersions,                   // { authConfig, appSettings } change tokens
});
const magicLinkEnabled = store.selectSettings((settings) => settings.get("magicLink") !== "false");
await magicLinkEnabled();                   // recomputed only when the settings change
```

Objects returned by `load()` and `smtpConfig()` are shared until the
configuration changes; treat them as read-only. A failed read falls back to the
environment configuration and empty settings, and is retried after the TTL.

Pass `defaults` for values that neither a row nor the environment sets. With
`{ auditLog: true }` the audit toggle is on while `AUDIT_LOG_ENABLED` is unset or
empty; only `false` turns it off. Without it the toggle stays off, so an app
without an audit log does not report one. `envAuthConfig(defaults)` takes the
same object:

```ts
const store = createConfigStore(repository, { defaults: { auditLog: true } });
```

`AuthConfig.appName` is the name users see during sign-in, such as the TOTP
issuer. It is `AUTH_APP_NAME` when set; otherwise the value of the app_setting
key passed as `appNameSetting`, then `defaults.appName`, then `"PodoKit"`. A
change to the setting changes the config version, so an auth instance built
from it is rebuilt:

```ts
const store = createConfigStore(repository, {
  defaults: { appName: "my-app" },
  appNameSetting: "site.name",
});
```

Set `sessionIdleTimeoutMinutes` to an integer from 5 through 10080 to build a
sliding server-side session lifetime. `null` keeps better-auth's default
seven-day lifetime. Generated applications expose this as **Automatic logout**
under Admin Settings → Authentication and apply changes to existing sessions.

Generated by [`@podosoft/podokit`](https://www.npmjs.com/package/@podosoft/podokit); most apps consume it
through the `auth` module rather than importing it directly.
