Make the `audit-log` module record every new account and name the user of sign-outs and token requests. `auth.signup` was recorded only for `POST /sign-up/email`, so an account created by a social provider's callback, a magic link, an email code, or an application's plugin left no sign-up entry, and one that waited for sign-up approval, which gets no session and so no `auth.login`, left no entry at all. The audit plugin now records `auth.signup` from Better Auth's user creation, whichever endpoint creates the account and even when the request then fails, with `metadata.method` and, for social sign-up, `metadata.provider`; `/admin/create-user` stays `user.create` only, now with the new user's id. `auth.logout` had no actor, because `/sign-out` loads no session and the session is gone by the after hook; it now names each account whose session the sign-out ended, and a sign-out without a session records nothing. Password resets by link, email code, or text message code and email verifications by link or code now name the account they changed, `user.session_revoke` names the owner of the revoked session, `user.stop_impersonate` names the administrator, and email changes by code are recorded.
