Restart a Kubernetes workload only for a Secret it reads. Every rendered pod template carried one checksum over the identity of every Secret the profile references, so changing an application Secret, such as `ADMIN_EMAILS`, made the next `podo deploy apply` restart the in-cluster PostgreSQL, Redis, and object storage StatefulSets, and a single-replica deployment answered readiness 503 for about 7 seconds. Each workload's `podokit.example.com/rollout-state-checksum` now covers only the Secrets it reads through env: the API and worker the API Secret, web the web Secret, and each dependency its own. The image pull and TLS Secrets restart nothing. Each dependency StatefulSet records its Secret and pod-template checksums in annotations on the StatefulSet, which do not restart pods, and `podo deploy plan` lists under `dependencyRollouts` whether each dependency is created, restarted, or kept running, and why, with a warning per restart; `podo deploy doctor` reports the same as `dependency-restart:<name>`. The first apply after upgrading keeps each dependency's pod template byte for byte while its live checksum still matches the current Secrets, so it restarts no dependency unless a Secret changed since the last apply, which the earlier checksum cannot attribute; the API, web, and worker roll once.
