Keep `podo dev` stacks of different projects apart on the shared development gateway. Every project's web container joined the shared `podokit-dev-gateway` network, and so did the API of a project with `webSocketPaths` or `apiPaths` in `.podokit/dev.json`. Compose registers each service under its plain name on every network it joins, so `web` and `api` resolved across projects there, and a web container could send its `/api` proxy requests (`BACKEND_INTERNAL_URL=http://api:5002`) to another project's API, which answered with that project's origin checks and rate limits. The web and API containers now stay on their project network. `podo dev` adds one gateway link per project instead: a small Traefik container named after the project's unique alias (`podokit-<name>-<hash>`) that joins both networks and passes TCP connections through to the web and API containers by aliases that exist only on the project network, so the gateway's proxy headers reach them unchanged. Its memory limit is 128 MiB (`GATEWAY_LINK_MEM_LIMIT`). After updating, run `podo dev down` and start each stack again so its containers leave the gateway network. A tool on the gateway network that reached the API at `http://podokit-<name>-<hash>-api:5002` now uses `http://podokit-<name>-<hash>:5002`.
