Let API clients call a generated app's `/api` through the production web server. A script, CLI, or MCP client sends no `Origin` header, and SvelteKit's cross-site form check, which runs before any hook or route, answered its `POST`, `PUT`, `PATCH`, or `DELETE` without a body or with a form-type body (an upload, for example) with `403 Cross-site POST form submissions are forbidden`. The Vite dev server skips that check, so the same request worked in development. The managed `vite.config.ts` now turns SvelteKit's check off (`csrf.trustedOrigins: ["*"]`), and a managed `hooks.server.ts`, which the fullstack template now ships and `admin-dashboard` extends, applies it first from the new `apps/web/src/lib/server/csrf.ts` with one difference: an `/api` request without an `Origin` header goes on to the API, whose authentication decides it. Browsers send `Origin` with every such request, so a cross-site form or `fetch` still gets `403` on `/api` and on pages, page form actions keep SvelteKit's rule, and `csrf.trustedOrigins` in `vite.extensions.ts` still lists the trusted origins. An app without `admin-dashboard` that has its own `hooks.server.ts` gets a conflict on update; keep the check by returning `refuseCrossSiteForm(event)` when it is not null before the rest of the hook runs. The new generated `tests/api/cross-site-forms.api.spec.ts` and the admin-dashboard `tests/api/no-origin-clients.api.spec.ts` check both sides against the built web server.
