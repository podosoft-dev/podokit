Keep the `podo dev` stack in step with the work tree. The API container now applies pending migrations before every start: `podo dev` sets `PODOKIT_DEV_MIGRATE=true` for it and the generated API runs `migrate:all` before it listens, so a migration that arrives with a pull, a rebase, or a new module reaches the development database instead of failing requests with 500 (Compose Watch restarts the API container when `apps/api/src` changes). A failed run leaves the API up and reports it in the log and as a down `migrations` readiness check; `migrate:all` now prints the migrations and Better Auth tables it applied. `podo dev watch` first runs `docker compose up --build --detach` from the work tree and then watches with `--no-up`, and while it watches it rebuilds a synced service that another command recreated from an image older than its synced files, which kept serving the source of the last build. The generated `vite.config.ts` adds a `podokit:refresh-recreated-files` plugin, because Vite and vite-plugin-svelte kept serving the first version of a component that was deleted and created again, as a rebase does. The development web container's default memory limit (`WEB_MEM_LIMIT`) is now 3 GiB instead of 2 GiB, which a full Playwright run against the Vite dev server exceeded. `runDevCommand` from the package API now returns a promise.
