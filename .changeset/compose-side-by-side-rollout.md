Keep a Docker Compose deployment answering while `podo deploy apply` and `rollback` replace it. They ran one `compose up`, which stops every changed service before it starts any of them, so a one-host deployment returned 502 until the new API, web server, and gateway had started one after another and passed their healthchecks, and an API holding a WebSocket or server-sent events stream first stayed in shutdown until Docker's 10-second stop timeout. The new API containers, and the new web server behind the gateway, now start beside the running ones, and the old ones stop only once the new ones are healthy; if a new container is not healthy, the containers the rollout started are removed and the old ones keep serving. The gateway no longer carries the release label, so it is replaced only when its own definition changes, and the web service sets `BUN_CONFIG_DNS_TIME_TO_LIVE_SECONDS` to `"0"` so it follows the API to its new containers. The object storage init job runs with the dependencies, before the migration, and a profile without managed dependencies no longer replaces running containers before the migration. The connection budget counts the old API containers beside the new ones.
