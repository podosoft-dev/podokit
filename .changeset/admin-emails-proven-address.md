Security: stop `ADMIN_EMAILS` from making an administrator of anyone who signs up with a listed address. The generated `auth.ts` gave the admin role and sign-up approval to every new account whose email was in `ADMIN_EMAILS`, checking only the address, so while email and password sign-up was open and email verification was off, anyone could register a listed address that had no account yet, such as a never-replaced `admin@example.com`, and become an approved administrator at once, bypassing sign-up approval. A listed address now makes an administrator only of an account that proves it as it is created: through `admin:bootstrap` or an administrator, or a sign-in that creates the account with a verified address (a social provider that reports the email verified, a magic link, or an email code). Any other new account with a listed address is refused with `PUBLIC_SIGNUP_DISABLED`. With `NODE_ENV=production` the API refuses to start when `ADMIN_EMAILS` lists an entry that is not an address or that is on a name reserved for documentation (`example.com`, `example.net`, `example.org`, `.example`, `.test`, `.invalid`, `.localhost`), and `podo deploy doctor` now reads that one value from the profile's `runtimeConfig`, the API Secret, or the API env file and fails on such an entry. The `admin-dashboard` Playwright seed no longer signs the administrator up: create it with `admin:bootstrap` before the suite runs.
